## CONSTRAINTS

- Keep the design explicit about browser-runtime memory versus app-owned JS heap.
- Treat external API authentication, CORS, quotas, and cache invalidation as boundaries.
- Do not expose service keys in JavaScript, manifests, service-worker caches, or logs.
- Do not claim live data behavior without a real KMA response or documented test fixture.
- Avoid framework, chart-library, web-font, and icon-package costs unless justified by evidence.
- Defer deployment-provider selection until an owner decision or approved plan requires it.
- Preserve a useful offline state and show data age prominently.
- Use Korean copy with natural CJK line breaking and accessible status semantics.

## VERIFICATION TARGETS FOR FUTURE IMPLEMENTATION

- Installability: valid manifest, service worker, icons, and standalone launch.
- Data: location-to-grid conversion and normalized KMA responses verified end to end.
- Offline: last successful forecast remains readable without a network connection.
- Security: no credential appears in built client artifacts or browser storage.
- Performance: initial payload, JS heap, DOM size, cache size, and idle network activity measured.
- Accessibility: keyboard operation, visible focus, contrast, reduced motion, and screen-reader labels.
- Responsive UI: narrow mobile and Windows desktop viewports captured and reviewed.
